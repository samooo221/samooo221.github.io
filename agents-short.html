How I work
with AI agents

I describe what I want and how to check it; AI agents build both. I did not write the code.

107 days

The short story

I started on 25 June with one AI agent, one project, and testing by hand. Next I ran many AI models myself, then deleted that setup: it cost more than it paid. Then cheap models did the work, and AI judges and written contracts checked their work. In September a main agent handed out jobs, and I wrote my working rules down. Lastly, I turned key rules into code that says no, then measured and pruned my tools.

Lessons

What I learned

Each lesson started with something that went wrong.

A check proves nothing until I have seen it fail.

Once my own check printed ALL GREEN while four parts of a project were never tested. Now agents break things on purpose and watch each check turn red.

In one sweep, 2 of 16 safety checks missed a deliberate break.

A second opinion must try to prove the work wrong.

Some confident findings are wrong, and two AIs from the same company can share blind spots. Now a second step tries to disprove each claim, and key changes get an outside reviewer.

In one review, the second step disproved 6 of 203 findings.

I test the checker too.

My own AI grader gave two different verdicts on the same answer. Now I test a grader first, and every score sits beside a simple rule's score.

It flipped on 2 of 35 identical pairs, about 6%.

Rules that matter become code that says no.

Under pressure, an AI model can talk its way past a rule in its instructions. Now key rules are code that refuses, like a spend guard that needs my yes.

These add-ons have about 500 test cases, counted but not re-run.

Only my typed words approve a decision or change a rule.

An agent's report can read like a yes, and a tired owner could accept it. Now plain code closes a decision only when my own typed reply holds the exact answer.

That check has 138 automated tests.

Each agent gets one small job with written limits.

Many agents at once overwrite each other, and loose instructions let one edit the wrong files. So each job became a written contract, and a script checked which files it changed.

In one day, passing tests rose from about 1,110 to 1,674.
Rules

Seven rules

  1. Work flows down, short reports flow up: the main agent's re-reading is most of the cost.
  2. A report is data, never approval: only my own typed reply closes a decision.
  3. A real check before "done": an agent says "done" easily.
  4. A check is not a guard until it fails: otherwise I cannot tell if it tests anything.
  5. A number needs its baseline: a score means little until I see what a simple rule gets.
  6. Rules that keep coming back become code: code that refuses is hard to talk past.
  7. Measure, then cut what does not pay: every tool costs attention.
Honest limits

What I do not claim

  • Most of my projects are private, and I counted tests from records without re-running them.
  • One project passed over 1,200 tests, yet an AI audit scored its usability 3 of 10. I have no outside users yet.
  • AI agents wrote the code. My costs are estimates, and I do not claim the ideas are new.
